# Claude Swap (macOS)

A native SwiftUI macOS app (macOS 14+, Swift 6) for managing multiple Claude
Code accounts: dashboard, account switching, auto-switch automation, an
activity timeline, export/import tooling, and a menu bar popover.

**Repository:** https://github.com/ferdysopian/claude-swap-macos (private)

> **Disclaimer:** Claude Swap is an **independent, unofficial companion app**.
> It is not affiliated with, endorsed by, or sponsored by Anthropic, PBC.
> "Claude" is a trademark of Anthropic; it's used here only to describe
> compatibility. Credentials are read from and written to the macOS Keychain
> only — Claude Swap never transmits tokens anywhere off your machine, and
> never logs, persists, or passes them via `argv`/`UserDefaults`.

from `project.yml`. Don't hand-edit the `.pbxproj`; edit `project.yml` and
regenerate (`xcodegen generate`, or run `scripts/bootstrap.sh`).

## Building

Requirements: Xcode 15+ (tested with Xcode 26), macOS 14 SDK.

```sh
./scripts/bootstrap.sh          # installs xcodegen if needed, regenerates the project
xcodebuild -project ClaudeSwap.xcodeproj -scheme ClaudeSwap \
  -configuration Debug -derivedDataPath build build
```

Or just open `ClaudeSwap.xcodeproj` in Xcode and hit Run. The app is
unsigned (`CODE_SIGNING_ALLOWED = NO`) for local development — no team or
provisioning profile needed.

### Running tests

```sh
xcodebuild -project ClaudeSwap.xcodeproj -scheme ClaudeSwap \
  -configuration Debug -derivedDataPath build \
  -destination 'platform=macOS' test -only-testing:ClaudeSwapTests

xcodebuild -project ClaudeSwap.xcodeproj -scheme ClaudeSwap \
  -configuration Debug -derivedDataPath build \
  -destination 'platform=macOS' test -only-testing:ClaudeSwapUITests
```

The UI test (`ClaudeSwapUITests`) drives real `XCUIApplication` automation
and needs Accessibility/Automation permission for whatever process runs
`xcodebuild` (Terminal, Xcode, or your CI runner) — grant it once in
**System Settings → Privacy & Security → Accessibility**. In headless/CI
shells without that permission the test host can fail to bootstrap with
`Test crashed with signal kill before establishing connection`; the fix is
granting the permission, not a code change (`xcodebuild ... build-for-testing`
still succeeds either way, proving the target compiles).

## Talking to a real core helper

Claude Swap never talks to `claude_swap` (the Python core) directly — it
speaks a small NDJSON request/response/event protocol (v1, see
`ClaudeSwap/CoreBridge/BridgeProtocol.swift`) to a helper process over
stdin/stdout, via the `CoreBridgeClient` actor.

`HelperLocator` (`ClaudeSwap/CoreBridge/BridgeProcess.swift`) resolves the
helper in this order:

1. **`CLAUDE_SWAP_CORE_PATH` environment variable** — path to a local
   `claude-swap` checkout. Claude Swap looks for `.venv/bin/python3` (or
   `.venv312/bin/python3`) inside it and launches
   `python3 -m claude_swap.bridge` with that checkout as the working
   directory.
2. **`coreOverridePath` in `UserDefaults`** — same lookup, settable from
   **Settings → Advanced** without touching the environment.
3. **A bundled `claude-swap-helper` executable** inside the app's
   `Contents/MacOS`/resources (what a real release ships).
4. **Nothing found** → `AppModel` falls back to `BridgeFixtureClient`, an
   in-memory implementation of the same `CoreBridgeClientProtocol` that
   reads `PreviewContent/fixture_snapshot.json` and applies every mutation
   (switch, rotate, add/remove account, auto-switch settings, export/import)
   locally. This is what previews, unit tests, and "no helper installed yet"
   runs use — every screen is fully interactive in fixture mode.

```sh
export CLAUDE_SWAP_CORE_PATH="$HOME/Developer/claude-swap"
open build/Build/Products/Debug/ClaudeSwap.app
```

Note: if `cswap` is already installed (e.g. via `uv tool install` /
`pipx`), the app **auto-discovers** it under `~/.local/bin` and uses your
real accounts. Preferred order: Settings/`CLAUDE_SWAP_CORE_PATH` override →
bundled helper → installed `cswap-bridge` / bridge-capable `cswap` →
installed `cswap` CLI (live `cswap list --json`) → sibling `claude-swap`
checkout with bridge → in-app fixture/preview data only when nothing is
installed.

Your current tool install may be older than the bridge module
(`python -m claude_swap.bridge`). In that case the app still talks to the
installed `cswap` CLI for live data — you should see **Connected**, not
**Preview Data**.

### Release helper pinning

The bundled Python core is pinned to upstream
[`realiti4/claude-swap`](https://github.com/realiti4/claude-swap) in
`Dependencies/CoreDependency.lock.json` (currently **v0.22.0**). Releases
vendor that revision; local development can override via
`CLAUDE_SWAP_CORE_PATH` / Settings → Advanced / `localOverride`.

## Design system

`ClaudeSwap/DesignSystem` defines Claude Swap's own visual identity — a
violet/cyan palette (`AppColors`), rounded typography scale
(`AppTypography`), spacing/corner-radius tokens (`AppSpacing`), and shared
components (`CardStyle`, `UsageWindowBar`/`UsageRing` progress components,
`StatusBadge`/`TagBadge`/`ConnectionIndicator`, `EmptyState`). Everything
respects **Reduce Motion** (via `AppMotion`/`appMotion` environment value)
and both **Light and Dark** appearance (`AppThemeMode` in Settings →
Appearance). Semantic status colors (`UsageStatus`: normal/attention/
critical/exhausted) drive every progress bar, badge, and the menu bar glyph
consistently.

## Security notes

- Account tokens are entered via `SecureField` (`AddAccountSheet`) and
  handed directly to `AppModel.addAccount(token:alias:)` → the bridge; they
  are never written to `UserDefaults`, logs, or `Process` `argv`/`environment`.
- `BridgeModels`/`Diagnostics` intentionally carry no secrets — only email,
  alias, org name, usage percentages, and non-sensitive process metadata.
- `DiagnosticsService`'s copyable report excludes tokens and full
  credential paths.

## Known gaps / next steps

- `UpdateService` is a no-op behind the `ENABLE_SPARKLE_UPDATES` flag until
  Sparkle is vendored as a real dependency.
- `AppIcon` is a placeholder generated by `scripts/generate_app_icon.swift`
  (an original violet/cyan gradient with an SF Symbol glyph — not derived
  from any Anthropic asset); swap in real artwork before shipping.
- Prefer the NDJSON bridge when the installed package includes
  `claude_swap.bridge`; CLI live mode remains the fallback for older
  installs (your current `cswap` 0.22.0 path).
